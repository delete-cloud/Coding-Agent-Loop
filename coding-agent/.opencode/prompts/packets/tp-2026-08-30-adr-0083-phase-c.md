## Freeze checklist

Every item is required before Phase C can be called complete:

- `EngineStepRequest` pairs one immutable `OperationStateVersion` with exactly one `EngineStepInput`.
- Each `EngineStepInput` variant has a stable consume-once input identity: `Initial`, `ModelGenerationCompleted`, `EffectSettled`, `ApprovalResolved`.
- `Initial` carries the admitted command batch and `mailbox_cut`.
- `ModelGenerationResult` carries final assistant content, optional finalized thinking, ordered tool calls, usage, and provider stop metadata. `StreamFrame` never carries tool calls or usage.
- `TransitionProposal.next_action` is required and is exactly the five-action union. No default or nullable compatibility path.
- `TransitionProposal.effect_plans` is an ordered tuple. It replaces the Phase B proposal's singular `effect_mutation`; one consume-once model result with multiple tool calls yields every plan exactly once and in provider order. The Phase B store UoW may retain its internal singular mutation input until Phase D because it is not a frozen AgentKit port signature.
- Effect and approval settlements carry tool-call, effect, and attempt identity, stable input identity, transition identity, owner epoch, and stable rejection/failure reason where applicable; one committed transition can consume each settlement only once.
- `PreparedEffectAction` can represent both dispatch preparation and an approval wait without a Phase D signature change.
- `DispatchAuthorizationRequest` carries `mailbox_cut`.
- `DispatchPermit` is opaque, single-use, and bound to session, effect/attempt identity, authorization transition, owner epoch, and idempotency identity.
- Commands have only applied, rejected, and superseded dispositions; rejection has a stable reason code; supersession has `superseded_by_command_id`; absent disposition means pending; no deferred disposition exists.
- `CommitRef`, `EffectPlan`, transition receipts, and Phase B CAS identity remain host-neutral and immutable. `ReconciliationRecord` pins effect/attempt identity, observed outcome, evidence reference, actor/owner epoch, and transition identity.
- Commit request types assign atomic ownership explicitly: action results re-enter the engine first; the resulting proposal plus settlement/disposition data is committed once by the matching transition or settlement request. Approval denial's rejection disposition, `prepared -> rejected` mutation, tool-result fact, and notice source belong to that one commit, never to a preliminary settlement plus a second proposal commit.
- Transition receipt identity/fingerprint semantics cover the complete ordered effect-plan collection without requiring a later public signature change.
- Commit results distinguish committed, exact replay, CAS conflict, stale owner, stale mailbox cut, invalid transition, and storage failure.
- `EffectExecutionResult` distinguishes completed, failed, and indeterminate dispatch. Cancellation after dispatch cannot claim non-execution.
- `CommittedFactNotice` can carry or reference the committed event-record identity required by Phase F without changing its signature later.
- `SegmentOutcome` has exactly the ADR fields for completed, blocked, safe-yield, cancelled, round-limit, and failed outcomes.
- Public AgentKit exports include every transitive type required to type the frozen Protocol signatures.

## Engine behavior

- `AgentEngine.propose` is synchronous/pure and has no adapter, store, mailbox, cursor, executor, plugin capability, frame sink, or committed-fact sink.
- Initial input admits pending commands and proposes the next explicit action.
- Model completion re-entry commits final assistant content and finalized thinking as pending facts. Every tool call becomes one ordered effect plan; two or more calls cannot be dropped, replayed, or reordered.
- Effect settlement re-entry produces exactly one pending durable tool-result fact and proposes the next model request, terminal action, or blocked action.
- Approval acceptance advances the prepared effect toward dispatch. Approval denial produces exactly one durable rejection tool-result fact and continues the model loop without a permit.
- The engine never retries or executes effectful tools.

## Coordinator behavior

- Own the loop: engine proposal -> matching fenced commit -> model/effect/approval action -> action result re-enters the engine -> the resulting proposal and settlement data commit atomically -> committed notices -> next action. Never commit a settlement fact before engine re-entry and then commit it again through the proposal.
- With fake ports, sequence prepared-intent commit and dispatch authorization before issuing a permit or calling `EffectExecutor`.
- Fake-port tests prove coordinator ordering and frozen request contents only. Live durable approval/mailbox migration, plugin capability cutover, and backend atomicity remain Phase D/E work.
- Poll `ControlProbe` at every ADR safe point. A raised generation returns safe yield while the durable command stays undispositioned.
- Derive and pass cancellation to live model generation. Uncommitted partial output is discarded.
- Await `FrameSink.emit` for bounded backpressure. Frame-sink failure disables later ephemeral frames and reports delivery failure without rolling back durable work.
- Emit `CommittedFactNotice` only after the corresponding prepared or settlement commit. Fact-sink failure disables later notices and reports delivery failure without mutating committed facts.
- Keep frame and committed-fact sink backpressure independent.
- Do not automatically retry indeterminate dispatch.
- Own settlement re-entry until terminal, blocked, interrupted, safe yield, failure, or configured round limit.
- Phase C may use fake ports in tests only. Do not add an in-memory production `CommitPort` implementation.

## Compatibility behavior

- Remove `Pipeline` and `PipelineContext` from imports and `__all__` in both `agentkit.runtime` and top-level `agentkit`.
- Sweep source, tests, docs, and examples for public namespace imports. Internal legacy callers must import the direct submodule when still needed.
- Remove top-level documentation that advertises `Pipeline` or `PipelineContext` as public API.
- Preserve the live legacy adapter behavior and wire schema.
- Pure committed-notice projection maps committed tool-call facts to `ToolCallDelta` and committed tool-result facts to `ToolResultDelta`. It never writes another fact or projects an uncommitted proposal.
- Outcome mapping: completed -> `NO_TOOL_CALLS`; round limit -> `MAX_STEPS_REACHED`; failed -> `ERROR`; cancelled and interrupt-driven safe yield -> `INTERRUPTED`.
- Existing doom-loop derivation stays adapter-side and may override completed to `DOOM_LOOP`; it is not derived from `SegmentOutcome` alone.
- Blocked and undispositioned safe-yield outcomes do not settle a root outcome.
- Any new exception-to-error mapping must use `exception_error_message` or an equivalent non-empty fallback. Never persist bare `str(exc)`.
