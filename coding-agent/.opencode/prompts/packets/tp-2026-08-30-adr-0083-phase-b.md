## Required contracts

- Add immutable typed values for `OperationStateVersion`, `TransitionProposal`, `StreamFrame`, `CommittedFactNotice`, commands and typed dispositions, `EffectPlan`, `ReconciliationRecord`, `commit_ref`, and transition receipts beside the existing runtime message primitives.
- AgentKit types stay host-neutral. `agentkit` must not import `coding_agent` stores, schemas, adapters, or product state.
- `OperationStateVersion` logically contains `run_id`, `revision`, `projection_epoch`, `commit_ref`, and `value`.
- `commit_ref` is store-stamped and contains `transition_id` plus optional contiguous `fact_seq_start`/`fact_seq_end`. It is not the physical session log head.
- The state CAS token contains `run_id`, `revision`, and `projection_epoch`; independent mailbox admission may advance physical `session_seq` without advancing engine revision.
- One fenced transaction validates owner and state CAS, allocates fact sequences, then commits the new state version, facts, dispositions, and effect mutation. Failure or CAS conflict changes none of them.
- Typed dispositions are `applied`, `rejected`, and `superseded`. Rejection requires a stable reason code. Supersession requires a stable replacement command reference. Commands absent from the disposition set remain pending; no `deferred` state exists.
- Transition receipts are immutable first-write-wins records keyed by `(session_id, projection_epoch, transition_id)` with a canonical mutation fingerprint. Exact retry returns the stored result before CAS and before any write. Fingerprint mismatch fails deterministically. Retry after an epoch change or later transition writes nothing.
- SQLite and PostgreSQL expose the same behavior and result types.
- Phase B must keep the legacy `settled` effect alias and rank-based replacement because live writers remain until Phase D. Do not remove or reinterpret them in this packet.
