# Developer Console Current State

Date: 2026-05-20

## Purpose

This map captures the repository state before the G54-G63 Developer Console /
Debug UI phase. The phase should add a debug/product surface over existing
Coding Agent APIs, stores, metrics, and observability contracts. It must not
rewrite AgentKit Core, change runtime semantics, bypass action policy, or
expose secrets/raw sensitive content beyond existing sanitized API contracts.

## Current HTTP Server And Router Structure

The HTTP surface is implemented in
`src/coding_agent/ui/http_server.py` as one FastAPI app:

- `app = FastAPI(...)` is defined in the same module as route handlers.
- `SessionManager` is a module-level service object used by the route layer.
- Request limiting is provided through `coding_agent.ui.rate_limit.limiter`.
- Authentication helpers live in `coding_agent.ui.auth`.
- Response schemas live in `src/coding_agent/ui/schemas.py`.
- Prometheus HTTP metrics are recorded by middleware in `http_server.py`.

There is no separate router package, no mounted `APIRouter`, no template engine,
and no existing `/console` route.

## Existing Static Or Web Assets

No existing web asset directories were found under `src/`:

## Recommended Console Shape

Recommended MVP: server-rendered HTML in `src/coding_agent/ui/http_server.py`
or a small adjacent Coding Agent UI module imported by that server.

Rationale:

- The repository has no frontend build stack.
- FastAPI is already the product HTTP boundary.
- Tests can use the existing ASGI `AsyncClient` patterns.
- Server-rendered HTML can reuse existing auth/session visibility checks.
- It avoids introducing a client-side framework for debug pages.

An API-only debug console fallback is acceptable for missing data domains, but
the phase goals explicitly require browsable `/console` pages. Static HTML + JS
is viable later if route count grows, but it would still call the same existing
HTTP APIs.
